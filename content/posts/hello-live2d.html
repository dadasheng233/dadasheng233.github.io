为啥AI写的网页都是一个风格？

大多数都太「正确」了：巨大的 Hero 标题、渐变按钮、整齐的卡片.......它们没有问题，但是看久了其实都一样，我们早晚会感到厌烦，对吧？而且越是精致，后期就越显得“奇怪”

其实手搓和AI没有啥区别，但是对于一个人来说，我们更需要：一个手搓的网页

这种「看着毫无意义的」的东西，反而最像一个人在经营自己的地方。

在你的眼里看似无用，可能是其他人眼里喜欢的角度

把小猫请进来

页面里的这个猫来自 Live2D 的 Tororo 模型。它不是会 GIF，而是由多个部件组成的实时模型：耳朵、眼睛、尾巴、身体都有独立的动作参数，所以转头和眨眼可以同时发生，也不会出现 GIF 那种生硬的循环接缝。 其实一开始我是想使用GIF的，但是GIF的体积太大了，加载慢，而且没有互动性（这句话是VSCODE填充的）具体我是怎么操作的我以后回来补充的（如果我能想起来的话我一定得带着对象一起做哈哈哈哈）

我用了 live2d-widget 作为加载器。模型、纹理、动作文件和 Cubism 2 运行时都放在本地，页面不再依赖外部 CDN。这样即使网络不好，小猫也只是晚一点出现，而不是永远缺席。

import('/vendor/live2d/waifu-tips.js').then(() => {
  window.initWidget({
    waifuPath: '/live2d/waifu-tips.json',
    cubism2Path: '/vendor/live2d/live2d.min.js',
    logLevel: 'warn',
    drag: false
  });
});

waifu-tips.json 里配置了模型路径、鼠标悬停时的台词，以及点击身体时的反应。模型自带一段 idle 动作和八段随机动作，加载器会在空闲时自己挑一段播放——这也是为什么它看起来总有自己的小情绪。

为什么不用视频或 GIF

因为猫需要「回应」。鼠标移到它身上，它会抬头；点一下身体，它会换一句台词；拖动页面时，它仍然稳稳地站在左下角。这些微小的反馈是视频给不了的。

当然，代价是它需要一个 WebGL 画布，也需要多下载几百 KB 的模型资源。对一个以文字为主的博客来说，这个代价不算小，所以我给它加了两道保险：

  • 只保留一张静态猫图；
  • 模型加载失败时自动显示备用猫图（其实这块我压根没做）。

动画不是越多越好

能把这个动画做的很好也需要点手搓

这些动画都很轻，单个看甚至察觉不到，但叠在一起，就非常好看，或者说非常：

下面的由AI书写

  • 入场：标题从上方淡入，导航逐项落下，卡片错峰上浮；
  • 悬停：卡片抬起 4px，封面缓慢放大，标题下划线展开；
  • 滚动：元素进入视口才出现，阅读进度条同步增长；
  • 转场：点击站内链接时，页面先轻轻暗下去，再进入下一页；
  • 小猫：呼吸、眨眼、转头、随机动作上述所有跟着鼠标的视线。

所有动画都遵守 prefers-reduced-motion。当系统开启「减少动态效果」时，位移和缩放会被关掉，只留下必要的透明度变化。一个舒服的页面，首先应该允许别人不看动画。

几个容易踩坑的细节

1. 猫的层级

Live2D 的容器默认层级很低，文章卡片一多，猫就会被压在下面。把 #waifu 的 z-index 提到内容之上、弹窗之下，这样就可以实现猫一直在正确的位置了。

2. 移动端不是缩小版桌面（没实现这个功能）

自己脑补一下）

3. 动画会阻塞内容

所有入场动画都用 CSS 完成，JavaScript 只负责添加 class。这样即使脚本加载失败，文章仍然是可读的。猫可以缺席，内容不能。

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}

最后

做完之后，我发现页面里最重要的部分其实不是猫，而是那些留白：标题和正文之间的距离、卡片与卡片之间的呼吸、猫和文字之间互不打扰的边界。
