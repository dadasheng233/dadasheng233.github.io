第一次看到那个站在页面左下角的小猫时，我盯着它看了很久。它不说话，只是偶尔眨眼、转头、伸懒腰，却让一个原本安静的页面突然有了呼吸。于是我想：自己的博客，也应该养一只。

这篇不是「如何完整复制某个站点」的教程，而是一次更诚实的改造记录：保留那种被小猫陪伴的感觉，把版式、配色和代码重新写一遍，最后做成一个真正能长期使用的个人博客。

先承认，我是为了那只猫

好看的个人主页很多，但大多数都太「正确」了：巨大的 Hero 标题、渐变按钮、整齐的卡片。它们没有问题，只是看久了像同一间样板房。

那只猫不一样。它没有承担任何信息功能，不引导点击，也不催促你订阅。它只是待在那里，偶尔动一下，像是在说：你慢慢看，我不着急。

这种「不有用」的东西，反而最像一个人在经营自己的地方。

一个博客的个性，往往不是由它写了什么决定的，而是由它允许自己保留多少「无用」决定的。

把小猫请进来

页面里的猫来自 Live2D 的 Tororo 模型。它不是一张会循环播放的 GIF，而是由多个部件组成的实时模型：耳朵、眼睛、尾巴、身体都有独立的动作参数，所以转头和眨眼可以同时发生，也不会出现 GIF 那种生硬的循环接缝。

我用了 live2d-widget 作为加载器。模型、纹理、动作文件和 Cubism 2 运行时都放在本地，页面不再依赖外部 CDN。这样即使网络不好，小猫也只是晚一点出现，而不是永远缺席。

import('/vendor/live2d/waifu-tips.js').then(() => {
  window.initWidget({
    waifuPath: '/live2d/waifu-tips.json',
    cubism2Path: '/vendor/live2d/live2d.min.js',
    logLevel: 'warn',
    drag: false
  });
});

waifu-tips.json 里配置了模型路径、鼠标悬停时的台词，以及点击身体时的反应。模型自带一段 idle 动作和八段随机动作，加载器会在空闲时自己挑一段播放——这也是为什么它看起来总有自己的小情绪。

为什么不用视频或 GIF

因为猫需要「回应」。鼠标移到它身上，它会抬头；点一下身体，它会换一句台词；拖动页面时，它仍然稳稳地站在左下角。这些微小的反馈是视频给不了的。

当然，代价是它需要一个 WebGL 画布，也需要多下载几百 KB 的模型资源。对一个以文字为主的博客来说，这个代价不算小，所以我给它加了两道保险：

  • 窄屏和「减少动态效果」模式下不加载模型，只保留一张静态猫图；
  • 模型加载失败时自动显示备用猫图，页面不会留下一个空荡荡的角落。

动画不是越多越好

原站最值得学的不是某个具体的特效，而是它的节奏：页面打开时，标题、导航、文章卡片依次出现；滚动到卡片时，它轻轻上浮；鼠标经过标题，下划线从中间展开；阅读文章时，顶部有一条很细的进度线。

这些动画都很轻，单个看甚至察觉不到，但叠在一起，页面就有了「被翻开」的感觉。我把自己保留的动效列了一张清单：

  • 入场：标题从上方淡入，导航逐项落下，卡片错峰上浮；
  • 悬停：卡片抬起 4px，封面缓慢放大，标题下划线展开；
  • 滚动：元素进入视口才出现，阅读进度条同步增长；
  • 转场：点击站内链接时，页面先轻轻暗下去，再进入下一页；
  • 小猫：呼吸、眨眼、转头、随机动作，以及跟着鼠标的视线。

所有动画都遵守 prefers-reduced-motion。当系统开启「减少动态效果」时，位移和缩放会被关掉，只留下必要的透明度变化。一个舒服的页面，首先应该允许别人不看动画。

几个容易踩坑的细节

1. 猫的层级

Live2D 的容器默认层级很低，文章卡片一多，猫就会被压在下面。把 #waifu 的 z-index 提到内容之上、弹窗之下，既不会挡阅读，也不会突然消失。

2. 移动端不是缩小版桌面

300×300 的猫放在手机屏幕上会占掉半屏。我的处理是 1180px 以下直接不加载 Live2D，改成一张静态猫图。这比强行塞进去更体面。

3. 别让动画阻塞内容

所有入场动画都用 CSS 完成，JavaScript 只负责添加 class。这样即使脚本加载失败，文章仍然是可读的。猫可以缺席，内容不能。

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}

最后

做完之后，我发现页面里最重要的部分其实不是猫，而是那些留白：标题和正文之间的距离、卡片与卡片之间的呼吸、猫和文字之间互不打扰的边界。

技术可以复制一套布局，但复制不了一个人愿意慢下来的程度。小猫只是一个提醒：这里不是信息流，是一间可以坐一会儿的房间。

如果你也想给自己的站点养一只猫，去翻翻 Live2D 的示例模型，或者干脆画一只自己的。它不需要很像，只要在你写东西的时候，愿意安静地待在那里就好。
